2Flujo de Autenticación de Usuarios

Login para admin_master, admin_normal, manager y user. Contraseñas hasheadas con Argon2. Sesión única forzada vía Redis (409 Conflict si hay sesión activa).

flowchart TD
    A["🖥️ Cliente"] -->|"POST /api/v1/auth/login/{tipo}\ntipo: user | admin | manager"| B{"FastAPI\nAuth Router"}
    B -->|"Buscar entidad por email"| C[("MySQL\n(admin/gerente/usuario)")]
    C -->|"Datos + password_hash"| D{"AuthService:\nauth_by_password()"}
    D -->|"Argon2 verify"| E{"¿Contraseña\nválida?"}
    E -->|"❌ No"| F["401 Unauthorized\nCredenciales inválidas"]
    E -->|"✅ Sí"| G{"SessionService:\ncheck_existing_session()"}
    G -->|"Redis: EXISTS session:{id}"| H[("Redis")]
    H -->|"Sesión activa encontrada"| I["409 Conflict\nSesión activa existente\n(debe hacer logout primero)"]
    H -->|"Sin sesión previa"| J["Generar JWT Token\nuuid4() → JTI\nPayload: sub, rol_id, jti, exp"]
    J --> K{"SessionService:\nsave_session()"}
    K -->|"SET session:{id} = JTI\nEXPIRE TTL: 3600s"| L[("Redis")]
    L --> M["200 OK\n{access_token, token_type: bearer}"]

    style I fill:#fef3c7,stroke:#f59e0b,stroke-width:2px

3Flujo de Autenticación de Dispositivos (Puzzle Criptográfico)

Autenticación sin contraseña usando AES-256-CBC + HMAC-SHA256. El servidor genera un challenge cifrado; el dispositivo demuestra posesión de la clave simétrica descifrándolo.

flowchart TD
    A["📱 Dispositivo IoT"] -->|"POST /api/v1/auth/login/device\n{device_id}"| B{"Auth Router"}
    B -->|"Buscar por device_id"| C[("MySQL\ntabla: dispositivo")]
    C -->|"device + encryption_key\n(AES-256)"| D{"AuthService:\nauth_by_puzzle_device()"}
    D --> E["1. Generar challenge aleatorio\nos.urandom(16).hex()"]
    E --> F["2. AES-256-CBC Encrypt\nIV aleatorio de 16 bytes\nPKCS7 padding"]
    F --> G["3. HMAC-SHA256\nsobre ciphertext\n(integridad)"]
    G --> H["4. Construir puzzle:\niv_hex : ciphertext_hex : hmac_hex"]
    H --> I["Enviar puzzle al dispositivo\n{puzzle, device_id}"]
    I --> J{"📱 Dispositivo:\n1. Verificar HMAC\n2. Descifrar AES-CBC\n3. Extraer challenge"}
    J -->|"Respuesta = challenge"| K{"¿challenge_response\n== challenge original?"}
    K -->|"❌ No match"| L["401 Unauthorized\nPuzzle inválido"]
    K -->|"✅ Match"| M["Generar JWT\nrol: device\nTTL: 86400s (24h)"]
    M --> N{"SessionService:\nsave_session()"}
    N -->|"JTI → Redis\nTTL: 86400s"| O[("Redis")]
    O --> P["200 OK\nDevice Bearer Token"]

    style P fill:#d1fae5,stroke:#059669,stroke-width:2px

4Flujo RBAC — Control de Acceso por Rol y Permiso

Triple verificación en cada request protegido: 1) JWT válido, 2) Sesión activa en Redis, 3) Rol y permisos en MySQL. Implementado como dependencias FastAPI en deps.py.

flowchart TD
    A["Request HTTP\nAuthorization: Bearer {JWT}"] --> B{"Dependency:\nget_current_user_or_device()"}
    B -->|"Decodificar JWT\njwt.decode()"| C{"¿Token válido\ny no expirado?"}
    C -->|"❌ Inválido/Expirado"| D["401 Unauthorized"]
    C -->|"✅ Válido"| E{"SessionService:\nverify_session()"}
    E -->|"GET session:{sub}"| F[("Redis")]
    F -->|"JTI no coincide\no no existe"| G["401 Unauthorized\nSesión inválida/expirada"]
    F -->|"JTI coincide ✅"| H{"Cargar entidad\ndesde MySQL"}
    H --> I[("MySQL\nadmin/gerente/\nusuario/dispositivo")]
    I --> J["current_user objeto\n(con rol_id)"]

    J --> K{"Decorator:\n@require_role(roles)"}
    K --> L{"¿rol_id del usuario\nen lista permitida?"}
    L -->|"❌ Rol no autorizado"| M["403 Forbidden\nRol insuficiente"]
    L -->|"✅ Rol válido"| N{"Decorator:\n@require_permission(perm)"}
    N -->|"SELECT FROM rol_permiso\nJOIN permiso"| O[("MySQL")]
    O --> P{"¿El rol tiene\nel permiso requerido?"}
    P -->|"❌ Sin permiso"| Q["403 Forbidden\nPermiso denegado"]
    P -->|"✅ Permiso concedido"| R["✅ ACCESO CONCEDIDO\nEjecutar endpoint"]

6Diagrama de Secuencia — Flujo Completo de Datos IoT

Flujo end-to-end: autenticación de dispositivo → envío de lecturas a MongoDB → consulta de reportes por usuario autenticado.

sequenceDiagram
    participant D as 📱 Dispositivo IoT
    participant API as 🐍 FastAPI
    participant MySQL as 🐬 MySQL
    participant Redis as ⚡ Redis
    participant Mongo as 🍃 MongoDB
    participant U as 🖥️ Usuario

    Note over D,U: ── FASE 1: Autenticación del Dispositivo ──
    D->>API: POST /api/v1/auth/login/device {device_id}
    API->>MySQL: SELECT * FROM dispositivo WHERE id_dispositivo = ?
    MySQL-->>API: device_data + encryption_key
    API->>API: Generar puzzle (AES-256-CBC + HMAC-SHA256)
    API-->>D: {puzzle: "iv:ciphertext:hmac"}
    D->>D: Descifrar puzzle con encryption_key compartida
    D->>API: {challenge_response: "decrypted_challenge"}
    API->>API: Verificar: response == original_challenge
    API->>Redis: SET session:device:{id} = JTI (TTL: 86400s)
    Redis-->>API: OK
    API-->>D: 200 {access_token: JWT, token_type: bearer}

    Note over D,U: ── FASE 2: Envío de Lecturas de Sensores ──
    loop Cada 30 segundos
        D->>API: POST /api/v1/sensors/device/reading
Headers: Authorization: Bearer {JWT}
Body: {temperature, humidity, battery, location}
        API->>Redis: GET session:device:{id} → verificar JTI
        Redis-->>API: JTI válido ✅
        API->>Mongo: db.sensor_readings.insert_one({device_id, readings, timestamp})
        Mongo-->>API: inserted_id
        API-->>D: 201 Created {reading_id}
    end

    Note over D,U: ── FASE 3: Login de Usuario y Consulta ──
    U->>API: POST /api/v1/auth/login/user {email, password}
    API->>MySQL: SELECT * FROM usuario WHERE correo = ?
    MySQL-->>API: user_data
    API->>API: Argon2 verify(password, hash)
    API->>Redis: SET session:user:{id} = JTI (TTL: 3600s)
    API-->>U: 200 {access_token: JWT, token_type: bearer}

    Note over D,U: ── FASE 4: Consulta de Reportes ──
    U->>API: GET /api/v1/devices/{id}/readings?limit=100
Headers: Authorization: Bearer {JWT}
    API->>Redis: Verificar JTI sesión usuario
    Redis-->>API: JTI válido ✅
    API->>MySQL: Verificar permisos: rol_permiso → view_reports
    MySQL-->>API: Permiso concedido ✅
    API->>Mongo: db.sensor_readings.find({device_id}).sort({timestamp: -1}).limit(100)
    Mongo-->>API: [{temperature: 23.5, humidity: 65.2, ...}, ...]
    API-->>U: 200 OK [{readings array}]

    Note over D,U: ── FASE 5: Logout y Limpieza ──
    U->>API: POST /api/v1/auth/logout
Headers: Authorization: Bearer {JWT}
    API->>Redis: DEL session:user:{id}
    Redis-->>API: OK
    API-->>U: 200 {message: "Sesión cerrada"}
